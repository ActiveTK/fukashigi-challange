# fukashigi-challenge

いわゆる「フカシギおねえさん問題」として知られる、n×nマスの左上の角から右下の角まで同じ点を2度通らない道順の数をフロンティア法を使って求めるGPU実装です。

実際にこのプログラムをNVLink接続の8x H200で動かして、27×27マスの値を求めました。

`109276227781641438773140825189073366698375750781415234587430038568878817805240411721164792545279603174461792609953735587143587104229597918313325900312636283963930548312008024064` （177 digits）

## 検証方法

答えは38個の16bit素数で割った余りをそれぞれ計算し、中国剰余定理で組み立て直したものです。

求めた素数と余りのペアは以下の通りで、どの1個を抜いて組み立て直しても同じ値になることを確認しています。実行ログは[こちら](results/27/res.txt)。

```
(65521, 12487), (65519, 24264), (65497, 3401), (65479, 51408), (65449, 8106), (65447, 13070), (65437, 63994), (65423, 26953), (65419, 34735), (65413, 34390), (65407, 23191), (65393, 15409), (65381, 7090), (65371, 59907), (65357, 2053), (65353, 47099), (65327, 57527), (65323, 43367), (65309, 51526), (65293, 44297), (65287, 30597), (65269, 53729), (65267, 8896), (65257, 55831), (65239, 57622), (65213, 6270), (65203, 43200), (65183, 8069), (65179, 24373), (65173, 32648), (65171, 62988), (65167, 35046), (65147, 727), (65141, 9452), (65129, 3596), (65123, 4732), (65119, 2328), (65111, 44134)
```

`make && ./build/fukashigi-cpu --crt results/27/res.txt` を実行すると余りから答えを組み立て直せて、出力は [results/27/report.txt](results/27/report.txt) と同じになります。本番で使ったバイナリは [Release](https://github.com/ActiveTK/fukashigi-challenge/releases/tag/27x27) にあります。
